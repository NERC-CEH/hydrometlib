# 1.0.0

The first stable, versioned public release of `hydrometlib`. Developed within UKCEH's FDRI programme, the library
provides a trusted collection of the standard calculations used to turn raw hydrometeorological measurements into
derived quantities. Each calculation is a single function that cites the paper or standard it comes from, is checked
against known-good values in its unit tests, and can be called with whichever of the common data types you already
have.

## Features

### Core

- Every calculation is a plain function, written as a pure [Polars](https://pola.rs/) expression, that takes the
measured quantities it needs and returns the derived quantity. Polars is the only runtime dependency.
- Calculations are grouped into four modules - `meteorology`, `evapotranspiration`, `cosmos` and `flux` - imported
from the top-level package: `from hydrometlib import cosmos, evapotranspiration, flux, meteorology`.

### Flexible inputs

- **Column arguments** - the measured quantities - accept a `pl.Expr`, a column-name `str`, a `pl.Series`, a
`pd.Series` or a `np.ndarray`, and the result comes back in the same form. A `str` is shorthand for `pl.col()` and
returns an expression; the Series and array forms are evaluated immediately.
- **Attributes** - the properties of where a measurement was taken, such as sensor height, latitude, or a calibration
coefficient - take the single number they usually are, or a column of any of the kinds above when the value varies
across rows.
- pandas and NumPy support is optional, via the `pandas` and `numpy` extras.

### Typing

- Every calculation contains `@overload` declarations in a `.pyi` stub, one per accepted input kind, so an editor knows
that passing a `pd.Series` returns a `pd.Series` and that a mixed-kind call is an error, without having to run it.
- The stubs are generated from the implementation signatures by `make stubs` rather than written by hand, and the
test suite fails if what is committed no longer matches the source.
- The implementations stay annotated `pl.Expr`, so their bodies remain type checked.

## Current set of calculations

### meteorology

Radiation balance and atmospheric-state variables: `net_radiation`, `mean_soil_heat_flux`, `mean_sea_level_pressure`,
`absolute_humidity`, `solar_zenith`, `albedo` and `is_snow_day`.

### evapotranspiration

The FAO-56 Penman-Monteith calculation, `potential_evapotranspiration_30min`, and the intermediate variables it is
built from - `saturation_vapour_pressure`, `actual_vapour_pressure`, `vapour_pressure_curve_slope`,
`latent_heat_of_vaporization`, `psychrometric_constant` and `wind_speed_height_correction`

### cosmos (soil moisture)

Various functions related to Cosmic-ray neutron sensor processing:

- Neutron count corrections - `neutron_intensity_factor`, `absolute_humidity_factor`, `atmospheric_pressure_factor` -
and `correct_counts` to apply them.
- Soil moisture from corrected counts: `volumetric_water_content`, `soil_moisture_index`, and the measurement depths
`effective_depth` and `d86`.
- Snow water equivalent for above-ground and below-ground (SnowFox) sensors - `snow_estimated_counts`,
`snow_water_equivalence`, `snow_water_equivalence_snowfox` - with the matching uncertainties
`sigma_snow_water_equivalence` and `sigma_snow_water_equivalence_snowfox`.

### flux

Energy-balance fluxes from eddy-covariance data: `latent_heat_flux`, and
`evapotranspiration_from_latent_heat_flux`.

## Documentation

- A [user guide](https://nerc-ceh.github.io/hydrometlib/) covering installation, a quick start showing the same
calculation in Polars, pandas and NumPy, the input rules in full, and chaining calculations together.
- Every example in the user guide is executed when the documentation is built, and the output shown beneath it is
what that code produced rather than something written by hand. The code lives in `docs/source/examples/`, is linted
and type checked with the rest of the project, and is run by the test suite.
- A reference page per calculation giving its equation, units, the meaning of every argument, and the paper or
standard it comes from.
